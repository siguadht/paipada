# 全屋多空间产品决策

日期：2026-10-01。以下记录的是开发前的产品决策；阶段 3-2 后来已实现并验收，真实验证与费用说明见[证据包](../evidence/阶段3-2/证据包.md)。

## 已定结论

同一个“我的家”下管理客厅、卧室等多个空间。用户给每个空间分别上传原始照片；全屋共用一套风格约束，空间可按用途补充个别要求。每个空间依次完成“原图 → 正面效果图 → 图上编辑与确认 → 该空间的 2.5D”。在“我的家”中切换空间，查看各自的正面图、2.5D、版本和商品热点。

此阶段不做一张拼接的全屋 2.5D 总图。多张室内照片不能可靠推断房间的相邻关系、尺寸与户型；若未来要准确的全屋总览，需另收户型图或空间连接与尺寸信息，再单独验证。

## 风格一致性的产品做法

1. 在家庭项目中保存共享的风格说明、色彩、材质与参考图，不让每个房间从零随机生成。
2. 用户确认第一个空间后，可把该结果作为后续空间的风格参考。每个空间仍以自己的原图约束门窗、墙体和视角。
3. 每个空间生成后由用户验收；共用风格提高一致性，不承诺家具、材质或空间结构自动完全一致。
4. 全屋共用的风格修改应清楚标示影响范围；已确认的其他空间不应被后台悄悄覆盖。是否批量重生需另行定义费用提示和人工确认。

## 对当前系统的影响

现有正式接口创建一份方案只接收一个 `photo_id`，`Design` 只保存一张原图和一个当前 2.5D 路径；当前 2.5D 从这份方案已确认的正面图生成。未来需新增家庭项目与空间归属，并让上传照片、生成版本、2.5D、热点和权限都明确绑定空间。要保留已有单房间方案的可读性，迁移或兼容方式在实施前确定。

现有 `/ui-preview` 的开始创作页已获产品经理认可，仍是单空间视觉稿。全屋入口、空间切换与共同风格设置在后续子阶段设计，不把本次方向确认误写为功能已完成。

## 实施顺序（产品经理已确认）

1. 先完成当前阶段 3-1 的单空间视觉与编辑链路，并交产品经理验收；未验收前不宣布 3-1 完成。
2. 验收后，在阶段 3 的后续子阶段开发“我的家”多空间：家庭项目、共用风格、房间切换、每房独立的正面图与 2.5D、版本及热点。
3. 开发前先核对历史单房间方案的兼容方式，并核算按房间增加的生图次数与费用提示；新增付费调用仍按项目费用规则确认。

## 实施状态（2026-10-01 更新）

阶段 3-1、3-2 均已验收。家庭项目、共享风格快照、房间切换及逐房独立生成已接入，旧单房间方案保留可读；本次授权下完成两房四张真实图。门窗结构和 2.5D 精度仍在[图片质量优化待办](图片质量优化待办.md)，阶段 4 尚未启动。
