# 第 2 阶段技术开发文档｜后端 MVP（终版 · 按最终实现修订）

> 配套：`docs/PRD/PRD.md`、`docs/PRD/方案.md`、`docs/阶段文档/技术适配声明.md`、`模型评测报告.md`、`真实冒烟报告.md`、`ControlNet评估.md`
> 本文档记录阶段 2（后端 MVP）的**最终实现**，覆盖 2-1（mock 全链路）与 2-2（真实生图 + 软装库 + 真实冒烟）。

## 一、阶段目标与完成情况
- 主链路：邀请码登录 → 上传照片 → LLM 理解 → 即梦生图（正面 + 2.5D）→ 人工审图 → 历史。
- 2-1 完成：项目骨架、邀请码登录、上传、LLM 理解、状态机、审图、历史、最小验收界面。回归修复后共 14 项 mock 测试。
- 2-2 完成：即梦真实生图（正面图生图 + 2.5D 同源图生图）、照片经火山 TOS 中转、内置软装库（styles/products）+ 热点商品映射、真实模型端到端冒烟。
- 暂缓：ControlNet 结构锁（评估见 `ControlNet评估.md`）；正式前端（阶段 3）。

## 二、技术适配摘要（最终）
- 默认方案：Python 3.12 + FastAPI + Pydantic + pytest + SQLAlchemy/SQLite。
- 按需模块：SQLite + SQLAlchemy（多用户隔离）、本地文件目录（图片）、TOS 对象存储（照片中转，图生图需要公开 URL）、后台异步（BackgroundTasks）、PyJWT（邀请码会话）、tos SDK、openai SDK（火山方舟 OpenAI 兼容）。
- 偏离/暂缓：任务队列、Alembic（2-1 用 create_all 建表，schema 稳定后再引入）、对象存储（TOS 仅作照片中转）、ControlNet。
- 开发路径：后端先行（阶段 2 带最小验收界面 `static/index.html`）。

## 三、技术栈与模型（最终选型）
| 项 | 最终选择 |
| --- | --- |
| LLM（理解意图） | **glm-5-3-flash**（评测 3/3 合规、~16s；豆包 turbo 176s 淘汰、DeepSeek 2/3 截断） |
| 生图 | **即梦 doubao-seedream-5-0-pro**（正面图生图 strength 0.7 保结构；2.5D 同源图生图 strength 0.5 与正面图一致） |
| 存储 | SQLite（`data/app.db`）+ 本地图片（`data/uploads`、`data/generated`）+ 火山 TOS（`paipaida-app`，照片中转） |
| 会话 | PyJWT（邀请码登录，7 天） |
| 性能 | 总流程约 **2.5 分钟**（产品经理拍板放宽，PRD 原 ≤30s 不可达） |

## 六、数据、资产与状态
- 表：`users`(id, invite_code, created_at, is_active)；`photos`(id, user_id, width, height, created_at)；`tasks`(id, user_id, photo_path, user_input, status, progress, current_step, llm_result, front_image_path, iso_image_path, design_notes, hotspots, layout_hints, review_score, reject_count, error_code, error_message, created_at, updated_at)。
- 图片访问：`/api/v1/files/uploads/{filename}` 与 `/api/v1/files/generated/{filename}` 都需登录，并在后端校验文件所有者；前端使用 Authorization 请求图片后以 blob URL 显示。
- 状态机：`pending → understanding → rendering → review → completed`；`reject`（<3 次）回 `understanding` 重生成，≥3 次 → `failed`；任一步失败 → `failed`。
- 数据隔离：所有查询按 `user_id` 过滤，他人任务一律 404。
- 软装库：`styles.json`（8 风格）、`products.json`（28 商品，含 category/style/brand/price），热点按"布局区域→品类→风格"映射商品。

## 七、API 设计（前缀 /api/v1，统一错误 `{"error":{"code","message"}}`）
| 方法/路径 | 说明 |
| --- | --- |
| POST /auth/login | 邀请码登录 → token |
| GET /auth/me | 当前用户 |
| POST /uploads | 上传照片（校验格式/真实类型/大小/安全文件名） |
| POST /tasks | 创建生成任务（后台执行） |
| GET /tasks/{id} | 轮询任务状态/结果 |
| POST /tasks/{id}/review | 审图（approve/reject + score） |
| GET /tasks | 历史列表（本用户，最近 50 条） |

## 八、Prompt 设计
- `understand.txt`：身份=软装设计 AI；输出结构化 JSON（style/colors/mood/budget/members/elements/avoid/sd_prompts/negative_prompt/design_notes/layout_hints）。含正反例；布局硬规则（沙发正对电视墙、电视背景墙简洁）；front 收尾"真人视角、24mm 镜头、写实摄影、8k"，isometric 收尾"室内轴测图、45 度等距俯视、无顶剖切、写实材质、真实光影、摄影级渲染"。
- 解析：`_extract_json`（宽容解析）+ `UnderstandResult`（Pydantic 校验），失败重试 1 次。

## 九、验收界面
- `static/index.html`（原生 JS + fetch）：邀请码登录、上传+描述、轮询进度、展示 LLM JSON + 两张图 + 设计说明 + 热点、审图 approve/reject、历史列表。临时验收工具，非正式前端。

## 十、测试要求（双层验收）
- 第一层 mock（pytest，14 项，离线）：登录成功/失败、上传校验、建任务、状态机、LLM 解析器、审图 approve/reject/重生成上限、数据隔离、图片归属与越权防护、错误路径。
- 第二层真实冒烟：已跑通（见 `真实冒烟报告.md`），LLM glm 3/3 首测合规，即梦正面图生图 + 2.5D 图生图端到端成功，总耗时 ~2.5 分钟。

## 十一、验收清单（产品经理照着做）
见 `docs/evidence/阶段2-1/证据包.md`、`docs/evidence/阶段2-2/证据包.md`。

## 十二、风险与待确认项
- **2.5D 无法精确匹配平面图**：即梦无结构锁能力，需 ControlNet+SDXL（已评估暂缓，见 `ControlNet评估.md`）。
- 图生图/文生图细节质量（沙发摆位、背景墙、绿植、卡通感）已在提示词层面迭代，仍需产品经理验收。
- 邀请码本身不写进项目状态文件。
- 无待产品经理决定的问题。

## 十三、交接给下一阶段（阶段 3）
- 已就绪：全套 API（登录/上传/建任务/查状态/审图/历史）、SQLite + 本地图片 + TOS 中转、最小验收界面、软装库。
- 阶段 3（正式前端）直接复用这套 API，做首页/加载页/结果页 + 对比滑块、热点、商品卡动效；不再重建后端。
