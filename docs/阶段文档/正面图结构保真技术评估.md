# 正面图结构保真技术评估

日期：2026-10-02。评估对象是“从用户房间照片生成效果图时，保住原有门窗、墙体、机位”，与此前暂缓的“严格匹配户型的 2.5D”不同。

## 已经验证的边界

- 现有 Seedream 5.0 Pro 路线输入原照片、风格参考和文字结构约束。客厅单张改进样例获验收；旧卧室两次真实生成都缩减右墙窗户，[对照记录](../evidence/非上线收口/卧室结构重验记录.md)。因此不能把提示词调整写成结构已稳定。
- 官方[图片生成 API](https://docs.volcengine.com/docs/ark/image-generation-api?lang=zh)列出单/多图输入、坐标和框选交互编辑。这些功能可指定编辑位置；公开参数中没有直接保证“门窗边界像素不变”的开关。后一句是根据公开参数与实测作出的推断，不等于官方声明所有结构约束方法都不可用。
- 已接入原图滑块对照、点位局部结构修正，现增加人工核对后再生成 2.5D 的页面流程；它拦截人眼可见的失败图，但不能提高模型首次生成的准确率。

## 推荐的下一次技术验证

2026-10-02 核对出一个具体画幅问题：旧卧室原图为 3:2，旧生成请求被固定选成 4:3。现已按火山官方列出的常见尺寸把 3:2 原图映射为 1872 × 1248，并做离线请求测试，见[画幅与遮罩记录](../evidence/非上线收口/画幅与门窗遮罩离线记录.md)。画幅变化只是可能的影响因素，未做新真实出图，不能宣称已修复窗户数量。

已在隔离环境用修正后的同画幅请求重验旧卧室，[真实结果](../evidence/非上线收口/卧室同画幅真实重验记录.md)仍把右墙三扇窗变成两扇，故停止 Seedream 连续尝试。接下来转向原照片画布上的遮罩局部生成，先保护门窗，再编辑家具和软装。手工门窗遮罩[离线原型](../evidence/非上线收口/卧室门窗保护遮罩原型.html)已可查看和导出，但当前 Seedream 请求**没有遮罩输入字段**，不能把该原型当成已接通的功能。需先确认支持遮罩的模型、运行方式与费用，测试窗框和窗帘交界质量。Hugging Face 的[局部重绘文档](https://huggingface.co/docs/diffusers/en/using-diffusers/inpaint)说明遮罩控制范围；[ControlNet 文档](https://huggingface.co/docs/diffusers/using-diffusers/controlnet)说明边缘、深度图可以引导生成。两者都不自动保证真实房屋几何完全一致。若卧室通过，再用第二张不同空间检验，且不能覆盖已验收方案。

验收时逐项看：远墙和右墙窗组数量、门的位置、墙角、顶面边界、地面及机位；同时看床/沙发、窗帘和软装是否自然。若结构仍错，不接入正式流程。若需要逐像素锁定某些门窗区域，还需额外评估区域保护与拼接质量，不能仅靠 ControlNet 文档作保证。

本评估初稿只做了接口和证据调查；随后对画幅修正另获单张 Seedream 费用授权并完成重验，记录见上方链接。遮罩路线仍未安装新模型或租用 GPU。GPU 规格、模型许可、耗时和费用需在具体原型配置确定后重新核算，并在创建计费资源前取得产品经理授权。

## 2026-10-02 遮罩方案选型补充

同画幅 Seedream 真实图已按单独授权重验，仍少一扇右墙窗。本项目现用的[Seedream 图片生成 API](https://docs.volcengine.com/docs/ark/image-generation-api?lang=en)支持坐标/框选编辑，但没有已验证可直接传入“黑白保护遮罩并保持其余像素不变”的生图参数；火山另有[MediaKit 遮罩擦除](https://docs.volcengine.com/docs/Intelligentprocessing/Imageerasurerepair?lang=zh)，用途是擦除并补背景，不等于按提示生成整套家具，因此不能直接替代当前生图。

可单独验证的开源候选是[SDXL Inpainting](https://huggingface.co/diffusers/stable-diffusion-xl-1.0-inpainting-0.1)：模型卡明确接收原图和遮罩，许可证标为 OpenRAIL++。但它不继承 Seedream 已验收的审美质量和商品参考能力；完整仓库约 20.8 GB，半精度 UNet 单文件约 5.14 GB，本机 M4/16 GB 还需考虑运行内存和生成时间。这些尺寸来自模型仓库，尚未在本机下载或实测。下一步先建隔离原型验证“黑区窗户像素保留、白区床和墙面能自然生成”，合格后再评估产品级接入；不能因为模型支持遮罩就承诺整体图好看或多房间稳定。

同日查到火山另一产品线的[即梦交互编辑 inpainting API](https://api.volcengine.com/api-docs/?serviceCode=cv&version=2024-06-06)：官方 API 列表明确描述原图、mask 和文本 prompt 的局部重绘。它不是本项目现用的方舟 Seedream `/images/generations`，需要单独核对服务开通、鉴权、输入尺寸和按次价格；当前未登录的公开文档页没有可靠的单次报价，因此没有调用。另一个[旧版涂抹编辑 API](https://docs.volcengine.com/docs/Intelligentvisionservices/InpaintingSmearEdit-1?lang=zh)公布了黑色保留、白色重绘及最大 4096×4096 的规则，但其[产品文档已标为“下线中”](https://www.volcengine.com/docs/86081/1804490?lang=zh)，不能把旧接口直接作为正式依赖。优先核查新版即梦接口的费用和权限；如果不可用，再考虑本地 SDXL 原型。

## 2026-10-02 即梦接口核对与离线输入准备

进一步在[即梦局部重绘接口文档](https://docs.volcengine.com/docs/JimengAI/JimengAI-interactiveeditinginpainting-interfacedocumentation?lang=zh)核实：提交任务使用 `CVSync2AsyncSubmitTask`、`jimeng_image2image_dream_inpaint`，两张同尺寸输入依次为原图、单通道灰度遮罩；黑色 0 保留，白色 255 重绘；提示词建议不超过 120 字。接口限制 JPEG/PNG、单图不超过 4.7 MB、最大 4096×4096。该接口在智能视觉控制台单独开通，并使用 `cv` 服务签名；现有方舟 API Key 不能直接替代。

[官方图像计费页](https://docs.volcengine.com/docs/JimengAI/JimengAI-imagegenerationbillinginstructions?lang=zh)当前列该能力按成功调用计费，一次一张 ¥0.20；页面同时明确以控制台实际接入价格为准。浏览器打开控制台时停在登录页，尚未核实本账号是否开通或有体验额度，也未点击开通、调试或提交任务。

已增加仅离线运行的 `backend/scripts/prepare_bedroom_inpaint.py`：从原遮罩原型读取五个门窗轮廓，按接口最大尺寸将旧卧室原图缩至 4096×2731，并输出完全同尺寸的单通道 `L` 遮罩；两文件均小于 4.7 MB，置于 git 忽略的 `data/qa-bedroom-inpaint-20261002/`。后端 39/39 测试通过；右墙窗、左门、可编辑地面的黑白采样通过。准备成功只说明输入合规，不说明局部生成的效果或窗框接缝合格。

下一步需先在已登录控制台核对开通状态、实际单价与额度，再取得单次新服务调用授权。建议不自动重试，只提交一张隔离卧室图；输出需人工对照三扇窗和边缘、家具质量。若不达标不接正式方案。

随后产品经理提供已登录控制台两张截图：该能力状态为“暂未开通”；“计费购买”页列免费试用 200 张、正式调用 ¥0.20/张、1 并发。离线遮罩进一步收紧为仅左墙下半部和地面可重绘，门窗、吊顶与其余墙面为黑色保留区；一次性提交脚本已准备且默认不调用，后端 40/40 通过。仍需产品经理确认开通新服务与最多一次真实调用；若开通页出现额外购买/不同价格须先停下重新确认。真实图质量仍未知。

产品经理之后明确授权开通与一次真实提交。结果见[单次真实审图](../evidence/非上线收口/卧室遮罩真实审图.html)及[记录](../evidence/非上线收口/卧室遮罩真实重验记录.md)：右墙三扇窗保留，软装已生成。输出黑区并非逐像素不变，硬回填原图会在床头产生接缝；因此“结构可控性在该样例明显改善”，但不能称为严格几何锁定或泛化完成。正式接入仍需产品经理看图验收和另一个空间的隔离验证。
