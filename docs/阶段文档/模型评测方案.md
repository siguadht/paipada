## 一、评测目标
从候选模型中选出两个正式模型：**LLM（理解意图）** 与 **生图模型（即梦）**，并据此确定决策台账 D2/D3（验收标准、瑕疵容忍度）。

## 三、评测样例（真实风格描述，5 条）
1. 奶油风，有猫，3 万预算，要温馨
2. 原木日式，采光差，要收纳
3. 现代极简，黑白灰，预算紧张
4. 法式复古，有宝宝，要安全
5. 北欧风，绿植多，要明亮

## 四、评测指标
- **LLM**：JSON 结构合规率（区分"首测即合规 / 重试后合规"）、字段完整度、`sd_prompts` 收尾约束遵守率、设计说明质量、耗时（目标 ≤3s）、单次成本。
- **生图**：正面效果图 + 2.5D 等距图各 1 张；看风格贴合、构图完整、2.5D 视角是否正确、耗时（目标 ≤20s）、单次成本。

## 五、决策方式（待样例打分）
- 我跑完把结果整理成表 + 样例图给产品经理；产品经理逐条"能/不能接受"打分（1–3 分，见通用手册第十节多媒体类维度：符合描述/质量可用/风格一致/无违规）。
- 据此写死 D2/D3 验收标准，并选定正式模型。数量/内容约束的超量（如设计说明超过 3 条）记为瑕疵交产品经理判断，不触发重试烧钱。

## 六、前提与产出
- 前提：产品经理先在方舟控制台开通上述候选模型（开通后告知，我即刻跑评测）。
- 产出：`docs/evidence/阶段2-2/模型评测报告.md`（含打分表 + 选定结论）。
