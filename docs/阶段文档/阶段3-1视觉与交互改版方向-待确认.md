# 阶段 3-1 视觉与交互改版方向（待产品经理确认）

日期：2026-10-01。当前只交付本机视觉稿，没有改动正式前端或提交新的付费生图请求。

## 已确认

- 参考图分为两种：整体风格参考、指定家具参考；与必填的原始房间图分开上传和标注用途。产品经理选择“两者都要，分开上传和标注用途”。
- 当前页面的点位圆形弹动不符合“鼠标移到家具上，整件家具像被选中”的交互期待。
- 修改需求入口需要显眼；当前六件演示商品数量不足；现有暖米色和砖红色视觉未获认可；生成结果的可控性需提高。

## 可看视觉稿

本机地址：http://127.0.0.1:8769/ 。点击顶部“开始创作 / 编辑结果”切换代表页；在结果页把鼠标移到沙发上，手机轻点沙发。静态文件在 Git 忽略目录 `data/视觉改版预览/`。若服务停止，从项目根目录运行：

```bash
python3 -m http.server 8769 --bind 127.0.0.1 --directory data/视觉改版预览
```

视觉稿使用非私人测试房间图、此前一次真实拆出的沙发图层，以及已用于本机演示的商品图。三张上传区按钮、模板、改需求按钮只演示布局；不会上传文件或调用模型。顶部页面切换、模板选择、反馈示例填入和沙发轮廓悬停可体验。正式页维持原状，待产品经理确认视觉方向后再实现。

### 第二版方向 B（2026-10-01，待看图）

产品经理反馈第一版“不很满意”。另做 [深色空间画布稿](http://127.0.0.1:8769/v2.html)：整张房间图占主要区域，两张参考图收进辅助栏；结果页让图片占主要面积，修改需求靠近画布，整件沙发悬停继续使用已验证的透明测试图层。配色改为深石墨与浅绿，避开第一版的冷白加电蓝工具后台感。文件仍在被 Git 忽略的本机目录，未改正式前端。

第二版已核对本机 HTTP 200、静态图片文件齐全和双页结构。浏览器任务被产品经理接管后，自动化浏览器按工具要求停止，故第二版的桌面/手机视觉与悬停没有完成浏览器复核；第一版的浏览器复核结果不能冒充第二版结果。

### 第三版方向 C：黑白创作工作台（2026-10-01，待产品经理看图）

产品经理明确要求“白加黑，其他颜色不要”，并指出前两版没有真正参考 AIGC 产品布局。第三版地址：[黑白创作工作台](http://127.0.0.1:8769/v3.html)。页面 UI 仅使用黑、白及灰阶；连示例房间图和参考图也暂时转为灰阶，以便单独判断版式。正式产品图片是否保持原色属于内容展示问题，视觉稿暂不代表该决策。正式前端仍未改动。

这版按实际官方产品页面的具体结构设计：

| 已核对的产品页面 | 页面上实际存在的结构 | 拍拍搭视觉稿的对应处理 |
| --- | --- | --- |
| [Midjourney Creating on Web](https://docs.midjourney.com/hc/en-us/articles/33390732264589-Creating-on-Web) | Imagine Bar 里输入提示词并附加图片；创建流里图片居中，右侧可回看提示词、参数和参考图；图片悬停后出现操作 | 顶部单一创作输入框同时放房间、风格、家具三种附件；效果图占编辑页中心，右侧显示改需求及使用的三张依据图，图片上出现操作 |
| [Magnific Image Editor](https://www.magnific.com/ai/docs/image-editor) | 图片在中心，工具在左侧；可用文字或图上标注指导局部编辑 | 效果图编辑页左侧极窄工具栏，中心大图，右侧修改描述；家具点选后在图附近提供替换、改色、删除 |

这不是复制两款产品的功能承诺。三张参考图的语义分工、先正面图后 2.5D、整件家具悬停与版本保留均依据拍拍搭既定流程。第三版用已有的一张沙发透明测试图层模拟整件家具被选中；尚未解决任意家具的识别和拆层。

第三版已做静态检查：本机 HTTP 200、12 个图片引用均存在、脚本 `node --check` 通过，CSS 中没有非灰阶的十六进制颜色。由于浏览器任务仍由产品经理接管，尚未完成第三版的桌面/手机浏览器视觉与悬停复核，不能把静态检查算作浏览器验收。

### 第四版：按 design-taste-frontend 搭建可操作 UI（2026-10-01，待看图）

产品经理要求调用该 skill 直接搭建 UI 效果。它明确将多步骤产品工作台列为适用范围之外，因此本轮只采用其中对本产品有效的简报推断、改版审计、反模板布局、单一配色、真实图片、动效目的、响应式和最终核查规则。设计判断：面向业主的图片创作与编辑产品，以房间图片为核心的黑白工作台；设计参数为布局变化 6、动效 4、信息密度 4。沿用 Next.js、React、Phosphor Icons 和原生 CSS，没有引入新的设计系统或依赖。

对现有首页审计：旧版暖米/砖红视觉与新决定冲突；首屏大标题、示例图和表单分成互相竞争的区域，房间本身不够突出；上传只有原始房间图，缺少已决定的两类参考图位置。此次建立独立 `/ui-preview` 路由，用真实的非私人技术样图和沙发图层搭出创作页与效果图编辑页，支持本地上传预览、模板填词、整件沙发悬停/点选、局部操作选择及明显的整图修改需求入口。

浏览器桌面 1200 px 和手机 390 px 已实际检查，截图与操作边界见 [黑白 UI 效果检查点](../evidence/阶段3-1/黑白UI效果/说明.md)。前端 Lint、类型检查和生产构建通过。该路由只演示 UI，不调用生图或保存上传内容；现有正式链路未替换，待产品经理看图反馈。

产品经理随后纠正第三版与第四版的关键误读：“黑白界面”只约束界面外壳和控件，不要求把房间、参考图、家具图变成黑白。第四版已删除全部图片灰度滤镜，照片恢复原色；选中工具与“修改需求”从黑色大块改为浅色或描边，主要生成操作保留黑色。桌面与 390 px 手机浏览器重新截图，图片计算样式为 `filter: none`，手机无横向溢出。该视觉解释记为后续前端改版约束。

### 第五版：画面优先的创作布局（2026-10-01，待产品经理看图）

产品经理认可上一版黑白灰控件与原色图片的配色原则，但不喜欢页面布局，要求参考 MiniMax Design 或小云雀。实际查看了 [MiniMax Design 官网](https://design.minimax.cn/) 与 [小云雀官网](https://xyq.jianying.com/)：前者当前是以客户端下载和作品展示为主的宣传页，后者的创作入口把内容画面放在上方、描述输入紧接其下。基于拍拍搭的“先看房间、再描述、再在效果图上改”的任务，选择后者的画面与输入关系作为布局参考；这是本项目的设计判断，不照搬品牌标识、图片、文案或页面代码。

`/ui-preview` 创作页现为居中的大幅原房间图，下方紧接修改描述、生成入口，再放风格图和指定家具图的可选入口及模板。原房间图完整显示，左右空余位置由同图模糊填充。结果页让原色效果图居中，选中沙发时图上显示“替换 / 改色 / 删除”，整体“修改需求”在标题旁，详细输入区在图片下方。白底、黑字、灰线及少量黑色主按钮沿用上一版配色。

桌面和手机截图、可操作范围及检查结果见 [创作布局重排检查点](../evidence/阶段3-1/创作布局重排/说明.md)。该路由仍是前端交互稿，演示生成和图上修改不会调用真实模型，正式业务页未替换。子阶段 3-1 仍待产品经理视觉与效果验收。

### 第六版：效果图编辑交互重排（2026-10-01，待产品经理体验）

产品经理明确认可第五版“开始创作”页，指出效果图编辑页交互感差。审计发现：点中沙发后的修改面板位于图片下方，操作者需要离开画面并滚动；常驻工具栏与图上操作重复，反馈不集中。此次保持已认可的创作页和黑白灰控件配色，仅重排 `/ui-preview` 编辑页。

现在沙发悬停时整件弹起，点击后操作条贴着图片出现；选择替换、改色或删除会立即展开对应输入。桌面输入贴在图旁，手机从底部出现。整体修改需求由顶部按钮直接打开。图片空白处可取消家具选中，颜色选项可快速填入描述。截图与浏览器检查见 [效果图编辑交互重排](../evidence/阶段3-1/效果图编辑交互重排/说明.md)。这仍是交互稿，没有真实修改图像；产品经理尚未验收。

### 第七版：创作与编辑页面布局一致（2026-10-01，待产品经理体验）

产品经理认为效果图编辑应与已认可的开始创作页保持一致，因为不满意效果图时仍需继续描述和生成。此前第六版的桌面侧面板、手机底部面板不再作为当前视觉方向。`/ui-preview` 编辑页现采用与开始创作相同的“大图在上、描述紧接下方、黑色主按钮、参考图在输入下方”顺序；整图反馈输入默认可见。点选沙发后保留图上的 Q 弹与替换、改色、删除按钮，但同一个输入区切换为局部修改要求，不另开面板。

桌面和 390 px 手机浏览器复核及截图见 [创作编辑同构检查点](../evidence/阶段3-1/创作编辑同构/说明.md)。开始创作页未改；编辑页仍是 UI 预览，真实重新生成、局部编辑和参考图持久化未接入这个路由。阶段 3-1 继续待产品经理验收。

### 第八版：白底的小云雀结构方向（2026-10-01，视觉验收已通过）

产品经理选择 B：继续使用白底与原色图片，但让页面结构更接近小云雀公开创作入口。独立 `/ui-preview` 的创作和编辑页统一为“宽幅主画面 → 居中模式切换 → 单一圆角创作框 → 横向示例”。原始房间、风格参考、家具参考入口放进同一个创作框；编辑时同一个框写整图问题或选中家具后的局部要求。黑白灰只作用于界面控件，房间图和参考图保持原色。示例是拍拍搭自身的房间约束与软装任务，不复制小云雀的内容。

浏览器桌面 1200 px 与手机 390 px 已检查，截图、操作说明与阶段闸门见 [白底结构稿检查点](../evidence/阶段3-1/小云雀结构白底稿/说明.md)。此稿仍不调用真实模型，也没有替换正式 `/` 页面；等待产品经理确认。

产品经理于 2026-10-01 回复“验收通过”，确认这套视觉与交互方向。此验收不等于正式功能完成：正式创建接口仍只有原房间照片与文字描述，参考图需要真实存储和参与生成；正式结果页还需保留编辑、版本恢复与 2.5D 流程。阶段 3-1 在正式接入与真实验收前保持进行中。

产品经理继续指出侧边栏缺失。依据[小云雀官方创作 Agent 画布手册](https://xyq.jianying.com/tutorials/creation-agent-canvas)中工作区左侧菜单、新建和历史的组织方式，预览页补充了拍拍搭的左侧导航：新建创作、创作/编辑切换、灵感示例、当前客厅和正式历史记录。桌面常驻，手机抽屉式打开；侧栏按钮已浏览器操作验证。截图见上述检查点。

## 实现边界

1. 整件家具悬停需每个生成版本对应的家具轮廓或透明图层。现有正式页只有单张平面图；此前仅验证一张沙发，不能声称全部家具已可识别。正式接入需解决拆层费用、延迟、遮挡、边缘瑕疵和版本缓存。
2. Seedream 5.0 Pro 官方图片生成接口支持多图参考；当前项目的生图服务只传原始房间图。两类参考图要进入后端校验、持久化、用户权限和提示词分工，不能只加两个前端上传框。参考图与模板提高引导性，不保证逐件精准复刻。
3. 现有本机真实产品图仅六件；其余 28 条是未经核实的示意商品资料。扩库时需逐件对应图片、名称和来源，不把旧示意价格误当真实售价。
