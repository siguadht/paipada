# 阶段 3-2：全屋多空间开发文档

更新：2026-10-01。状态：功能、真实双空间生图与技术检查已完成；图片质量和阶段验收待产品经理确认。

## 目标与范围

一个账号可建多个“家”；每个家保存风格文字与可选参考图。每个房间独立上传原图、生成正面效果图、编辑与确认，再生成自己的 2.5D；在“我的家”中切换房间。旧单空间方案继续从“全部方案”查看。

同一套共享风格只能提高一致性，不能保证模型对结构、家具和材质的遵循程度。此阶段不拼接全屋 2.5D，不自动批量重生旧房间。

## 兼容与数据

- 新增 `homes`、`home_spaces` 两张表；不改现有 `designs` 表，不搬迁或删除既有方案。
- `home_spaces.design_id` 唯一，房间与原有方案一对一。版本、正面图、2.5D、热点沿用设计方案自己的归属。
- 房间创建时复制家庭风格文字到 `style_snapshot`；共享参考图写入该方案的风格参考记录。以后修改家设置不影响旧房间及已发出的生成任务。
- 用户可主动将**已确认并完成 2.5D** 的房间正面图设为后续房间的风格参考。服务端复制为当前用户所属的参考图；原方案不变。
- 家、空间、参考图与方案均在后端校验用户归属。旧单空间 `POST /designs` 请求仍可用。

## 页面与流程

入口 `/homes`：加载中、空列表、项目列表、错误信息分开显示。创建家可填名称、共享风格、参考图；选家后可修改全屋设置或添加空间。`/?home=<id>` 使用原有创作框，增加房间名称、共享风格说明及本次生成费用确认。提交后进入原 `/design/<id>` 编辑链路；返回“我的家”可打开其他房间。桌面白底工作台和手机抽屉沿用 3-1 已验收的视觉。

生成前费用提示按 2026-10-01 火山[官方价格表](https://docs.volcengine.com/docs/ark/model-pricing?lang=zh)：Seedream 5.0 Pro 1.5K 及以下单图输出 ¥0.30，第二张起输入图 ¥0.02/张。新房间 1～3 张输入，图片约 ¥0.30～0.34/次；模型 POST 最多因失败重试一次，估计上限 ¥0.68，另有文字模型与临时存储费用。真实账单以火山为准。UI 明示并要求勾选，后端要求 `cost_confirmed=true`；2.5D 仍需用户在结果页单独点击确认。

## 接口契约

统一错误结构沿用 `{"error":{"code","message"}}`，需邀请码登录：

| 接口 | 用途 | 关键字段 |
| --- | --- | --- |
| `GET /api/v1/homes` | 列自己的家和房间 | `homes[]`，每个空间带原方案摘要 |
| `POST /api/v1/homes` | 新建家 | `name`, `style_text`, `style_photo_id?` |
| `GET /api/v1/homes/{id}` | 查看一个家 | 房间名称、风格快照、方案状态与版本 |
| `PUT /api/v1/homes/{id}` | 修改之后房间的共用设置 | `name`, `style_text`, `style_photo_id?` |
| `POST /api/v1/homes/{id}/style-from-space/{space_id}` | 主动沿用已确认房间风格 | 无请求体，返回更新后的家 |
| `POST /api/v1/designs` | 在家中创建房间方案 | 原字段外加 `home_id`, `room_name`, `cost_confirmed=true` |

无权限的家与空间统一按不存在处理。参考图继续使用受保护的文件接口。创建房间及生成结果均持久化 SQLite 和本地文件；模型任务与旧方案相同，可从方案 URL 恢复。

## 验证与已知限制

- 离线后端测试 **28/28** 通过：两房间关联、风格快照、参考图继承、已确认房间沿用、跨用户隔离、费用确认、旧方案访问。
- 前端类型检查、Lint、生产构建通过；桌面与 390 px 手机的全屋空态已在浏览器检查，无横向溢出。
- 额外用隔离 SQLite 数据库启动、停止并重启真实 API 进程；新建的家庭项目及共享风格可由同一账号重新读取，不触碰正式用户数据。
- 经产品经理单次授权，使用现有客厅原图和 Pexels 公开卧室实拍，通过正式页面生成客厅与卧室各一张正面图和一张 2.5D；客厅确认后主动设为卧室风格参考。两房持久化并可刷新切换，结果见 [3-2 证据包](../evidence/阶段3-2/证据包.md)。
- 人工对比发现共享材质/配色基本成立，但门窗结构保持不足；2.5D 为视觉微缩场景而非精确户型。产品经理已于 2026-10-01 验收通过 3-2，并将图片质量问题列为后续优化；详见[图片质量优化待办](图片质量优化待办.md)。
- 视觉质量延续 3-1 待办：电视背景墙不够好，2.5D 尚非严格等距，家具点选不是完整轮廓识别。这些不能由多空间数据结构自动解决。
