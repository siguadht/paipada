# 前端技术适配声明｜阶段 3

## 项目判断

拍拍搭是面向业主的图片主导软装产品。产品经理在 2026-09-30 确认交互顺序：首次只生成正面效果图；用户直接点选软装，进行删除、替换、改色或整体风格修改；满意后才生成 2.5D。选中时希望有轻微 Q 弹反馈。沿用已认可的结果页 v5 白底、暖色与大图视觉。

## 技术选择

- Next.js App Router、React、TypeScript strict、原生 CSS 设计变量；交互由 Client Components 承担。
- 集中 API 客户端；任务、版本与图片归属由 FastAPI 决定。受保护图片经 Bearer 鉴权读取后用 Blob URL 展示，不把模型密钥送到浏览器。
- 编辑页用真实图片点击坐标，映射到 0–999 模型点位。Q 弹使用局部图像层动画提供即时反馈；它不是物体精确分割。
- 方案版本持久化在 SQLite，旧阶段 2 Task API 保留；新流程用独立 Design API，避免改变已有验收链路。
- 图片调用采用当前 Seedream 5.0 Pro。编辑 API 使用点位 prompt；确认后用当前正面图作 2.5D 输入，并关闭模型默认水印。

## 页面和状态

- `/`：邀请码登录、上传、描述、建方案。
- `/design/[id]`：生成状态、效果图点选编辑、前后对比、版本恢复、确认后查看 2.5D。
- `/history`：当前用户的方案列表。
- 主要状态：`pending → understanding → rendering_front → front_ready ↔ editing → rendering_iso → completed`；失败保留原版本并展示可操作的错误。

## 当前偏差和风险

- PRD 初稿中的“首次双图同生”已被产品经理新决策覆盖。阶段 2 旧流程仍保留双图同生。
- 商品库当前有 28 件文字元数据，无商品图；替换入口将它们作为搭配参考，不能冒充真实购买链接或精确 SKU 还原。
- 点位可指导模型修改，但并不提供独立家具遮罩；当前 Q 弹是点击区域反馈，尚未做到家具轮廓整体弹起。
- 2.5D 热点与设计说明目前不能自动对每次图片修改精确同步；页面明确标明初始说明可能过时。
- 真实模型可按点位改色并从编辑后的图生成微缩空间视图；最终视觉质量与等距精度由产品经理验收。
