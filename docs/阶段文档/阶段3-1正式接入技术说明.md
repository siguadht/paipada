# 阶段 3-1 正式工作台接入技术说明

更新：2026-10-01。状态：一体式创作框已获产品经理验收；三图真实模型冒烟经授权重试成功，正式创建与整图反馈重生已实测，第二版效果审图及局部编辑/2.5D 待完成。

## 页面与真实链路

- `/`：邀请码登录保留；登录后使用已验收的白底工作台结构。原房间为必传，风格图和家具图各自可选，三张图明确标注用途；描述可用示例模板填入。创建时先上传图片，随后一次性提交方案 ID 与参考图 ID。
- `/design/[id]`：左侧工作台导航、上方原色效果图、图下视图切换和默认展开的整图反馈框。点图后仍可替换、改色、删除；用户新增参考图时，在下次编辑/整图重生前上传并更新方案引用。版本恢复、2.5D 确认和热点逻辑继续沿用原有业务代码。
- `/history`：接入同一侧栏。手机以抽屉形式展开；页面实际检查无横向溢出。

## 数据与接口

- 新增 `design_references` 表，不修改已有 `designs` 表列，保存 `design_id`、参考用途与上传照片 ID。
- `POST /api/v1/designs` 可选接收 `style_photo_id`、`furniture_photo_id`；`PUT /api/v1/designs/{id}/references` 可在效果图可编辑时更换引用。两者都验证格式、文件存在、当前用户归属；非法或跨用户引用返回统一错误，不创建方案/不覆盖旧引用。
- 方案响应增加 `references`（受保护的图片 URL）和 `reference_ids`。旧方案返回空对象，保持旧客户端的创建请求可用。
- Seedream 请求以原图/当前效果图为图 1，风格图、家具图按角色次序追加到 `image` 数组；提示词写清各图用途，避免把风格图的房间结构复制到原房间。临时 TOS 对象在请求完成后逐个删除。无 Key 离线测试仍保留显眼 MOCK 标识，不能作为真实效果结论。
- 单图请求格式保持原字符串；没有参考图的旧方案不改变生图调用参数。

## 费用与验证边界

[火山图片生成 API](https://docs.volcengine.com/docs/ark/image-generation-api?lang=zh)支持 Seedream 5.0 Pro 多图输入；[官方模型定价](https://docs.volcengine.com/docs/ark/model-pricing?lang=zh)当前说明首张输入免费，第 2 张起每张 ¥0.02，单图输出在 1.5K 及以下 ¥0.30。原图 + 风格图 + 家具图的一次请求，图片项约 ¥0.34；现有网络/服务端失败路径最多自动再试一次，极端情况下图片项约 ¥0.68，另有少量临时对象存储费用，实际以账单为准。首次经授权的三图生成失败；产品经理再次授权后，第二轮以 1 次 POST 得到 HTTP 200 和真实图片。输出、素材局限及清理证据见[三图真实冒烟记录](../evidence/阶段3-1/多参考图真实冒烟/说明.md)。这是直接调用后端服务，并非正式网页全流程；实际计费需看火山账单，再次付费调用需重新授权。

后端 26/26 个离线测试通过，含跨用户参考图拒绝、引用持久化、多图输入次序和请求协议异常清理；前端 TypeScript、ESLint 和生产构建通过。创作框现将三类图片、描述与生成按钮合于同一输入区，产品经理已验收这一局部。桌面 1280/1440 px、手机 390 px 与窄平板 768 px 已检查；768 px 侧栏改用抽屉，主图宽度由约 473 px 增至 705 px。已有方案的效果图和 2.5D 视图已只读复核。产品经理仍需验收真实生成效果与完整编辑手感，阶段 3-1 不能据此宣布完成。

## 正式页面首版实测（2026-10-01）

按产品经理要求从正式页面登录、上传原房间及两类参考图、填写描述并提交，需求理解和 Seedream 正面生图均成功，版本 1 持久化且刷新后可加载。输出与截图见[正式流程实测](../evidence/阶段3-1/正式流程实测/说明.md)。结果虽清除了杂物并加入软装，但原右侧窗户移到中央、机位发生变化，结构保留未达要求；产品经理审图、图上编辑与 2.5D 尚未完成。

用户反馈后，正式页面成功保留版本 1 并生成版本 2；第二版图片和检查结论见[正式流程实测](../evidence/阶段3-1/正式流程实测/说明.md)。当前 `design_notes` 仍来自首版，页面虽标注“初始说明”，其中“悬浮电视柜”与新版落地电视柜要求矛盾；后续应使说明跟随版本更新。

2026-10-01 补充：产品经理接受木地板但认为电视背景墙有重大问题，并要求预览 2.5D。使用第二版正面图生成独立预览，不改变方案确认状态或正式 2.5D 字段。图片见[正式流程实测](../evidence/阶段3-1/正式流程实测/说明.md)；人工观察仍是斜俯视微缩模型，不满足严格等距轴测。

产品经理随后表示本次 2.5D 预览总体可接受、可通过体验验收，但正面效果图不好。记录为样例主观验收，不把它解释为严格等距目标完成；正式方案仍未确认正面图，局部编辑也未完成实测。
