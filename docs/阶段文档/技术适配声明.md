## 1. 产品形态判断
- **目标用户**：25–40 岁想装修/改造的业主（真实用户画像，核心受众）+ 设计师（辅助角色）。用途是面试演示（你演示、面试官观看），但产品按给真实用户用的标准做。
- **产品类型与核心任务**：AIGC 软装效果图生成。上传房间照片 + 一句风格描述 → LLM 理解意图出结构化方案（风格/色彩/预算/prompt/设计说明/热点）→ 空间结构锁透视 → 生成 2 张图（正面效果图 + 2.5D 等距图）→ 前端双 Tab 展示 + 对比滑块 + 热点商品卡 + 设计说明。
- **核心交互**：一次生成 + 分阶段状态展示 + 人工审图（你本人 approve/reject + 评分≥4 通过）。是固定编排工作流，不是多轮对话，也不是动态工具调用。
- **用户规模与权限**：多用户（瞄向）——有登录、每人只看到自己的数据，权限在后端判断（上线硬底线 #7）。
- **开发路径**：**后端先行**（默认路径 A）。理由：最大技术风险是"火山即梦能否稳定出 2.5D 等距 + 结构锁透视"，必须先验证后端核心链路再投入前端精美；阶段 2 会附一个最小可视化验收界面（单个 HTML）用于看图和审图。
- **当前阶段范围**：阶段 1 只做技术适配，不写代码；下一阶段 2 做后端 MVP（上传→LLM→生图→审图→结果 + 最小验收界面）。

## 6. 需要产品经理决定的问题
### 问题 1：登录方式用哪种？（多用户方向已定，此项定 D5 具体实现）
- 为什么重要：多用户必须有登录，登录方式影响实现量与是否引入额外短信平台费用。
- 选项：A 账号+密码（邮箱/手机号注册 + 密码登录）/ B 邀请码（发码才能进）/ C 手机号+短信验证码（体验好，但要接短信服务、有费用）
- 推荐：A。标准、通用、无额外短信费用，是"瞄向多用户"的正路；阶段 4 上线可再考虑换验证码。
- 不选的后果：C 要额外接短信平台并产生费用；B 更像内测，不够"正式产品"。
