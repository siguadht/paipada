# ControlNet 方案评估（平面图 → 精确匹配的 2.5D / 结构锁生图）

> 项目：拍拍搭 · 日期：2026-09-29 · 应产品经理要求评估

> **2026-10-02 复核说明：**本文原本评估的是“平面图 → 精确 2.5D”，其中“ControlNet 能做到匹配户型”“正面图不需要结构控制、基本对得上”等句子属于当时的方案预估，并非实测结论。后续卧室正面图重验把原图右墙三扇窗生成成两扇，已直接否定“正面图结构稳定”的判断。边缘或深度条件可以引导空间布局，但能否保住门窗数量、位置与相机视角，须用本项目照片单独验证，不能预先承诺。该复核不改变产品经理此前接受的示意 2.5D 边界；正面图结构控制的下一步评估见 [正面图结构保真技术评估](正面图结构保真技术评估.md)。

## 一、它解决什么
- 当前即梦是"黑盒"生图，**锁不住结构**：上传平面图/照片后，出的 2.5D 是"通用房间"，对不上用户真实户型。
- ControlNet（MLSD 直线检测 / Canny 边缘检测）专门锁"墙线、轮廓、布局"，能做到**按平面图出匹配的 2.5D**。

## 二、技术方案
- **ComfyUI + SDXL + ControlNet MLSD**（本地或云 GPU）。
- 流程：平面图 → MLSD 提取墙线 → ControlNet 锁结构 → SDXL 按"等距轴测"提示词生图。
- 后端通过 ComfyUI 的 HTTP API 调用。

## 三、部署选项对比
| 项 | 本地 Mac（M4 / 16GB） | 云 GPU（AutoDL 等，国内） |
| --- | --- | --- |
| 可行性 | 能跑，但 16GB 偏紧 | 轻松 |
| 单张耗时 | **约 3–5 分钟** | 约 15–30 秒 |
| 费用 | ¥0（无租赁） | 约 ¥1–2.5/小时（3090/4090），一次演示约 ¥2–5 |
| 演示体验 | 太慢，不推荐 | 快，可接受 |
| 部署 | 首次装 ComfyUI+模型 ~10GB | 同左，另需开机关机 |

## 四、工作量与时间
| 环节 | 估算 |
| --- | --- |
| ComfyUI 环境 + SDXL/ControlNet 模型下载（~10GB） | 2–3 小时 |
| MLSD 工作流调试（平面图 → 2.5D，需几轮调参） | 2–3 小时 |
| 后端对接 ComfyUI API | 1–2 小时 |
| **合计** | **约 1 天** |

## 五、风险与如实说明
- **出图"好看度"待实测**：SDXL 基础模型出图质量可能不如即梦（即梦是商业调优模型）；ControlNet 锁结构强，但"漂亮程度"要调几轮才知。
- **需真实平面图样例**：手上没有产品经理的真实平面图，效果只能拿公开样例先验证，精度到不到位需实测。
- 正面图（核心）其实**不需要** ControlNet——即梦图生图已能"基本对得上"房间结构。

## 六、推荐结论
- **暂缓 ControlNet**：它只服务于"2.5D 精确匹配平面图"，而 2.5D 已被产品经理定为"重要但也不重要"；且需 ~1 天 + 云 GPU + 效果待实测，投入产出不划算。
- **当下走法**：正面图用即梦图生图（保结构、对得上自己家）；2.5D 用 V4 通用等距版（作为"好玩/示意"，不承诺精确匹配）。
- **未来触发**：产品经理确认"平面图 → 精确 2.5D"成为核心卖点时，再启动本方案（评估已备好，随时可动工）。
