# 正面图结构确认关口

日期：2026-10-02。旧卧室原图两次生图都改变了右墙窗户；本轮只改本地流程，没有新增付费模型请求。

## 现在怎样验证

1. 登录本机[拍拍搭](http://127.0.0.1:3000/)，打开一张尚未确认的效果图，例如[已验收的客厅隔离样例](http://127.0.0.1:3000/design/c4963a77-b33d-4df5-b5b3-ef5f24673ae3)。
2. 点“对照原图并确认”。页面切到可拖动的原图对比，逐项核对门窗、墙地面、机位。没有全部勾选时，“确认本版，生成 2.5D”不可点。
3. 发现错误时点“有问题，回到效果图修正”，再点效果图中的错误位置，选“参照原照片修正这一处”。该局部修正会调用付费模型，实际使用前须确认费用。
4. 新机位概念图显示“仅设计示意”的确认项，不会要求用户谎称它与原照片机位一致。

本轮浏览器实测：桌面 1200 px、手机 390 px 均无横向溢出；未勾选时确认按钮禁用，三项勾选后可启用，点“有问题”能回到正面编辑。桌面与手机截图：[桌面](结构确认-桌面.png)、[手机](结构确认-手机.png)。**浏览器没有点最后的生成按钮，未产生图片费用，也未改动该已验收方案。**

对比组件还修正了异比例裁切：原图与结果比例接近时保留滑块；例如旧卧室原图为 3:2、正面图为 4:3 时，改为上下展示两张完整图片。浏览器核对为 2 张完整图片、无裁切容器和横向溢出。这样审查门窗时不会把滑块的裁切当成模型生成差异。

后端新增按设计 ID、正面版本、图片文件名保存的结构核对记录。新界面发来的核对项缺失或与当前机位类型不符时返回结构化 400 错误；记录与 2.5D 排队状态同一次数据库提交。为了不破坏既有客户端，旧版无核对请求的 `confirm` API 暂保持可用；**这是一道新版页面的人工闸门，不是所有 API 客户端都无法绕过的强制质量门槛，也不会自动识别窗户错误。**正式多用户上线前需复核兼容策略与后端强制范围。

验证：后端 38/38，前端类型检查、Lint、生产构建通过；本机 API 重启后新表存在，原方案仍为 `front_ready`，新增核对记录为 0（因为浏览器没有实际确认）。
